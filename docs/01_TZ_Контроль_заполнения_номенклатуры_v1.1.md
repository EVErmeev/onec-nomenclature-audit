# Техническое задание
## Внешний отчёт 1С «Контроль заполнения номенклатуры»

**Версия:** 1.1  
**Дата:** 01.08.2026  
**Актуальный проект OpenCode:**

```text
D:\OpenCode\onec-nomenclature-audit
```

Старый каталог:

```text
C:\Users\egore\OneDrive\Документы\Default Project
```

не использовать.

---

## 1. Цель

Разработать готовый внешний отчёт 1С:

```text
КонтрольЗаполненияНоменклатуры.erf
```

для конфигурации:

```text
Управление торговлей, редакция 11
Версия конфигурации: 11.5.22.129
Платформа: 8.3.27.1559
```

Отчёт должен анализировать справочник:

```text
Справочник.Номенклатура
```

и выявлять проблемы заполнения данных.

---

## 2. Использование MCP

MCP используется для:

- подтверждения конфигурации и версии;
- подтверждения объекта `Справочник.Номенклатура`;
- подтверждения фактических реквизитов;
- поиска примеров в коде;
- проверки запросов;
- выполнения безопасных запросов на чтение.

Запрещается использовать объекты и реквизиты, наличие которых не подтверждено через MCP или ранее сохранённые результаты исследования.

Ранее уже подтверждены:

- `Справочник.Номенклатура`;
- 57 реквизитов объекта;
- 16 используемых реквизитов;
- запросы отчёта;
- отсутствие прямых реквизитов `Штрихкод`, `Серия`, `Характеристика`.

Повторять полное исследование конфигурации не требуется. Повторные MCP-вызовы выполнять только при необходимости уточнения конкретного объекта, реквизита или запроса.

---

## 3. Обязательный результат

Должен быть создан действительный внешний отчёт:

```text
D:\OpenCode\onec-nomenclature-audit\dist\КонтрольЗаполненияНоменклатуры.erf
```

Пользователь должен иметь возможность:

1. открыть 1С:Предприятие;
2. выбрать «Файл → Открыть»;
3. выбрать `.erf`;
4. увидеть готовую управляемую форму;
5. нажать `Сформировать`;
6. получить результат.

Пользователь не должен:

- создавать внешний отчёт;
- создавать форму;
- создавать реквизиты формы;
- добавлять команды;
- размещать элементы;
- копировать BSL-код;
- вручную собирать `.erf`.

---

## 4. Функциональные требования

На форме должны находиться параметры:

| Параметр | Тип | Значение по умолчанию |
|---|---|---|
| Учитывать помеченные на удаление | Булево | Ложь |
| Учитывать группы | Булево | Ложь |
| Только с проблемами | Булево | Истина |
| Максимальное количество строк | Число | 1000 |

На форме должна быть команда:

```text
Сформировать
```

Результат должен выводиться в табличном виде.

Минимальные колонки:

- Ссылка;
- Код;
- Наименование;
- Родитель;
- Проблема;
- Проверяемый реквизит;
- Текущее значение;
- Рекомендация.

Ссылка должна позволять открыть карточку номенклатуры.

---

## 5. Обязательные проверки

1. Не заполнено наименование.
2. Элемент помечен на удаление.
3. Одинаковое наименование.
4. Одинаковый код.
5. Не заполнена родительская группа, если проверка применима.

Дополнительные проверки выполнять только по подтверждённым реквизитам:

- Артикул;
- ВидНоменклатуры;
- ЕдиницаИзмерения;
- СтавкаНДС;
- ТоварнаяКатегория;
- ГруппаФинансовогоУчета;
- ТипНоменклатуры;
- НаименованиеПолное;
- Производитель;
- ЦеноваяГруппа;
- КодДляПоиска.

Проверки `Штрихкод`, `Серия`, `Характеристика` не реализовывать как проверки прямых реквизитов `Справочник.Номенклатура`.

---

## 6. Требования к форме

Форма должна содержать:

- основной реквизит `Объект`;
- реквизит результата;
- четыре реквизита параметров;
- команду `Сформировать`;
- кнопку `Сформировать`;
- командную панель;
- элементы ввода параметров;
- поле результата;
- обработчики событий;
- корректные `DataPath`;
- зарегистрированную форму в `ChildObjects`;
- корректную ссылку в `DefaultForm`.

Модуль формы не должен содержать инструкций пользователю:

```text
Разместить на форме
Добавить реквизит
Создать кнопку
Скопировать код
```

Все элементы должны быть созданы автоматически.

```text

9. erf-validate
10. erf-build
11. Анализ build.log
12. erf-dump
13. Проверка обратной выгрузки
14. Открытие .erf в 1С:Предприятие
15. Проверка команды Сформировать
16. Проверка результата и фильтров
```

---

## 9. Сборка

Сборку выполнять только штатными средствами платформы 1С через skill:

```text
erf-build
```

и команду:

```text
/LoadExternalDataProcessorOrReportFromFiles
```

Запрещён способ:

```text
XML + BSL → ZIP → переименование в .erf
```

ZIP-fallback не использовать.

---

## 10. Проверка результата

После сборки обязательно выполнить:

```text
erf-dump
```

Обратная выгрузка должна содержать:

- корневой объект отчёта;
- зарегистрированную форму;
- модуль объекта;
- модуль формы;
- реквизиты формы;
- элементы формы;
- команду `Сформировать`.

После этого готовый `.erf` необходимо открыть в 1С:Предприятие.

## 11. Тесты

Минимальные тесты:

1. `.erf` открывается.
2. Форма отображается.
3. Видны все параметры.
4. Доступна команда `Сформировать`.
5. Команда выполняется.
6. Результат выводится.
7. Ссылка открывает карточку номенклатуры.
8. Фильтр помеченных элементов работает.
9. Фильтр групп работает.
10. Режим «Только с проблемами» работает.
11. Лимит строк соблюдается.
12. Ошибка выводится в копируемом виде.

## 13. Критерий приёмки

Задача считается выполненной только при прохождении цепочки:

```text
form-compile
→ form-validate
→ erf-validate
→ erf-build
→ erf-dump
→ открытие в 1С
→ функциональный тест
```

Если любой обязательный этап не выполнен, итоговый статус:

```text
НЕ ВЫПОЛНЕНО — <КОНКРЕТНАЯ ПРИЧИНА>
```

Успешный статус:

```text
ВЫПОЛНЕНО — ГОТОВЫЙ ВНЕШНИЙ ОТЧЁТ СОБРАН И ПРОВЕРЕН
```

Статус `Выполнено частично` не использовать.
