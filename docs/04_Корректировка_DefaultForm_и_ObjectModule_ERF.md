# 2. Что найдено внутри контейнера

Внутри файла зарегистрирован внешний отчёт:

```text
КонтрольЗаполненияНоменклатуры
```

Внутри контейнера присутствует форма:

```text
MainForm
```

В форме присутствуют:

- реквизит `Объект`;
- реквизит `Результат`;
- четыре параметра;
- команда `Сформировать`;
- элементы формы;
- модуль формы.

Следовательно, сама форма физически попала в бинарный файл.

При этом платформа при открытии пытается найти имя:

```text
ВнешнийОтчет.КонтрольЗаполненияНоменклатуры.Form
```

вместо полного имени фактически существующей формы:

```text
ВнешнийОтчет.КонтрольЗаполненияНоменклатуры.Form.MainForm
```

Это указывает на некорректное или неполное заполнение свойства основной формы отчёта.

---

# 3. Основная причина текущей ошибки

В корневом XML внешнего отчёта свойство `DefaultForm` должно явно ссылаться на фактическую форму:

```xml
<DefaultForm>ExternalReport.КонтрольЗаполненияНоменклатуры.Form.MainForm</DefaultForm>
```

Одного добавления:

```xml
<ChildObjects>
    <Form>MainForm</Form>
</ChildObjects>
```

недостаточно.

`ChildObjects` регистрирует форму как дочерний объект, но не гарантирует, что платформа выберет её как основную форму при открытии отчёта.

Для добавления формы необходимо использовать skill:

```text
form-add
```

с установкой формы по умолчанию:

```text
--set-default
```

Либо необходимо явно и корректно заполнить `DefaultForm` в корневом XML.

# 4. Дополнительная критичная проблема

В бинарном контейнере обнаружен вызов из модуля формы:

```bsl
ОтчетОбъект.СформироватьОтчет(Результат, Настройки, Отказ);
```

Однако внутри бинарного файла не обнаружены:

- процедура `СформироватьОтчет`;
- текст запросов;
- обращения к `Справочник.Номенклатура`;
- реквизиты запроса `Артикул`, `ВидНоменклатуры`, `ЕдиницаИзмерения` и другие;
- создание объекта `Запрос`;
- оператор `ВЫБРАТЬ`.

Это означает, что объектный модуль с основной логикой отчёта не попал в итоговый `.erf` либо был собран пустым.

После исправления основной формы вероятна следующая ошибка:

```text
Метод объекта не обнаружен: СформироватьОтчет
```

или отсутствие результата при нажатии `Сформировать`.

# 5. Возможная причина отсутствия объектного модуля

Для иерархической XML-выгрузки внешнего отчёта объектный модуль должен находиться по пути:

```text
<ИмяОтчёта>\Ext\ObjectModule.bsl
```

Для текущего проекта ожидаемый путь:

```text
src\КонтрольЗаполненияНоменклатуры\Ext\ObjectModule.bsl
```

Недопустимые варианты:

```text
src\ObjectModule.bsl
ObjectModule.bsl
src\КонтрольЗаполненияНоменклатуры\ObjectModule.bsl
```

Если файл лежит не в каталоге `Ext`, платформа может собрать отчёт без нужного объектного модуля.

# 6. Почему предыдущая приёмка была некорректной

OpenCode указал статус:

```text
ВЫПОЛНЕНО — ГОТОВЫЙ ВНЕШНИЙ ОТЧЁТ СОБРАН И ПРОВЕРЕН
```

Но фактически отчёт не был открыт в 1С до передачи пользователю.

Были выполнены только:

- структурная валидация XML;
- сборка;
- обратная выгрузка;
- проверка состава файлов.

Эти проверки подтверждают структуру и возможность преобразования XML в `.erf`, но не подтверждают:

- корректный выбор основной формы;
- успешное открытие формы;
- компиляцию модулей при открытии;
- выполнение команды `Сформировать`;
- наличие объектного модуля;
- выполнение запросов.

Статус «собран и проверен» нельзя использовать до фактического открытия отчёта в 1С:Предприятие.

# 7. Задание для OpenCode

Продолжи исправление существующего проекта:

```text

```

Не создавай проект заново.

## 7.1. Исправить основную форму

Открой корневой XML внешнего отчёта и проверь свойство:

```xml
<DefaultForm>
```

Оно должно иметь точное значение:

```xml
<DefaultForm>ExternalReport.КонтрольЗаполненияНоменклатуры.Form.MainForm</DefaultForm>
```

Проверь также:

```xml
<ChildObjects>
    <Form>MainForm</Form>
</ChildObjects>
```

Не оставляй:

```xml
<DefaultForm/>
```

Не указывай:

```xml
<DefaultForm>ExternalReport.КонтрольЗаполненияНоменклатуры.Form</DefaultForm>
```

Не используй имя формы без `MainForm`.

Предпочтительный способ:

1. использовать `form-add`;
2. указать `MainForm`;
3. использовать параметр `--set-default`;
4. затем применить существующий JSON DSL через `form-compile`.

Если форма уже существует и `form-add` отказывается её создавать повторно, исправь `DefaultForm` напрямую и проверь результат через `form-info`, `form-validate` и `erf-validate`.

Проверь, что он содержит:

- экспортную или доступную из формы процедуру `СформироватьОтчет`;
- фактические запросы;
- обращение к `Справочник.Номенклатура`;
- формирование результата;
- обработку исключений.

Если текущая процедура не имеет `Экспорт`, проверь доступность метода из модуля формы и при необходимости объяви:

