## 5. Обязательный порядок выполнения

### Этап 1. Проверка проекта

1. Проверить структуру каталогов.
2. Найти текущие исходники.
3. Найти старые скрипты сборки.
4. Найти ZIP-fallback.
5. Удалить или отключить ZIP-fallback.
6. Переместить отклонённый файл в `rejected`.

### Этап 2. Проверка исходников

1. Выполнить `erf-validate`.
2. Выполнить `form-info` или `form-decompile`.
3. Зафиксировать ошибки:
   - `ChildObjects`;
   - `DefaultForm`;
   - реквизитов;
   - команд;
   - элементов;
   - событий;
   - `DataPath`;
   - модулей.

### Этап 3. Создание формы

1. Использовать `form-patterns`.
2. Сформировать JSON DSL.
3. Создать форму через `form-compile`.
4. Проверить через `form-validate`.
5. Исправлять до успешной проверки.

### Этап 4. Исправление отчёта

1. Исправить корневой XML.
2. Зарегистрировать форму в `ChildObjects`.
3. Проверить `DefaultForm`.
4. Согласовать UUID.
5. Проверить модуль объекта.
6. Проверить модуль формы.
7. Удалить инструкции по ручной сборке.
8. Выполнить `erf-validate`.

### Этап 5. Сборка

1. Использовать `erf-build`.
2. Использовать штатную платформенную сборку.
3. Сохранить `build.log`.
4. При ошибке анализировать лог.
5. Исправлять исходники и повторять сборку.
6. Не использовать ZIP.

### Этап 6. Обратная выгрузка

1. Выполнить `erf-dump`.
2. Сохранить `dump.log`.
3. Проверить структуру выгрузки.
4. Повторно выполнить `form-validate` и `erf-validate`.

### Этап 7. Пользовательский тест

1. Открыть `.erf` в 1С:Предприятие.
2. Проверить форму.
3. Проверить параметры.
4. Нажать `Сформировать`.
5. Проверить результат.
6. Проверить ссылку.
7. Проверить фильтры.
8. Проверить лимит строк.
9. Зафиксировать результат в `logs\functional-test.md`.
