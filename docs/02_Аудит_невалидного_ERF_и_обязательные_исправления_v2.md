# Аудит предыдущего результата
## Невалидный файл `.erf` и обязательные исправления

**Версия:** 2.0  
**Дата:** 01.08.2026  
**Актуальный проект:**

```text
D:\OpenCode\onec-nomenclature-audit
```

---

## 1. Итог аудита

Предыдущий файл:

```text
KontrolZapolneniyaNomenklatury.erf
```

не является готовым внешним отчётом 1С.

Файл имел сигнатуру ZIP:

```text
50 4B 03 04
PK
```

Внутри находились:

```text
ExternalReport.xml
ObjectModule.bsl
Forms\MainForm\Form.xml
Forms\MainForm\Ext\Form\Module.bsl
```

Это набор исходников, упакованный в ZIP и переименованный в `.erf`.

Такой способ недопустим.

---

## 2. Ошибки предыдущей реализации

### 2.1. Неверный способ сборки

Было выполнено:

```text
XML + BSL → ZIP → переименование в .erf
```

Файл не создавался платформой 1С.

### 2.2. Форма не была создана

В `ExternalReport.xml` была ссылка на основную форму, но:

```xml
<ChildObjects/>
```

оставался пустым.

В XML формы отсутствовали:

- реквизиты;
- команды;
- элементы;
- привязки;
- кнопка;
- поле результата;
- параметры;
- командная панель.

### 2.3. Модуль формы требовал ручных действий

Модуль содержал комментарии вида:

```text
Разместить на форме
Добавить флажок
Добавить кнопку
Добавить ТабличныйДокумент
```

Это означает, что готовая форма не была создана.

### 2.4. Использовались отсутствующие реквизиты

Модуль обращался к:

```text
Объект
Результат
```

но они не были объявлены в XML формы.

### 2.5. Команда не была создана

Процедура `Сформировать` присутствовала в BSL, но команда формы и кнопка в XML отсутствовали.

### 2.6. Проверка была формальной

Проверялось наличие файлов и строк внутри ZIP, а не валидность объекта платформой 1С.

---

## 3. Обязательные исправления

1. Удалить недействительный ZIP-файл из `dist`.
2. Перенести его в:

```text
rejected\
```

3. Удалить ZIP-fallback из всех локальных скриптов проекта.
4. Создать полноценный корневой XML внешнего отчёта.
5. Зарегистрировать форму в `ChildObjects`.
6. Создать форму через `form-compile`.
7. Проверить форму через `form-validate`.
8. Проверить отчёт через `erf-validate`.
9. Собрать `.erf` через `erf-build`.
10. Выполнить `erf-dump`.
11. Открыть `.erf` в 1С:Предприятие.
12. Выполнить функциональный тест.

## 4. Запрещённые действия

- считать SHA-256 подтверждением валидности;
- передавать пользователю исходники вместо готового отчёта;
- оставлять ручное создание формы пользователю;
- завершать задачу без `erf-dump`;
- завершать задачу без открытия в 1С.

## 5. Работа при проблеме с базой

Если `F:\UT_Demo` не открывается в Конфигураторе:

1. не утверждать, что причина в Apache без подтверждения;
2. проверить активные процессы 1С и Apache;
3. создать изолированную копию базы;
4. проверить копию;
5. использовать временную или stub-базу, если это поддерживается skill;
6. проверить доступные версии платформы;
7. сохранить полную диагностику.

Ошибка первой попытки сборки не является внешней блокировкой.

Внешней блокировкой могут считаться только подтверждённые причины:

- платформа не установлена;
- отсутствует лицензия;
- отсутствует доступ к базе;
- неизвестны необходимые учётные данные;
- операционная система запрещает запуск;
- отсутствуют права записи;
- база повреждена и это подтверждено проверкой.

---

## 6. Проверка готового результата

Готовый файл принимается только если:

1. создан платформой 1С;
2. успешно прошёл `erf-dump`;
3. обратная выгрузка содержит форму;
4. обратная выгрузка содержит команду `Сформировать`;
5. обратная выгрузка содержит реквизиты и элементы формы;
6. файл открывается в 1С:Предприятие;
7. команда `Сформировать` запускается;
8. результат выводится.
